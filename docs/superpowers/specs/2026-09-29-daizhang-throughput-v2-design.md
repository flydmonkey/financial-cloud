# 代账吞吐第二曲线 · 产品设计规格

> Date: 2026-09-29  
> Status: approved; implementation W0+W1 in progress  
> Owner: product (autonomous iteration under user full authorization)  
> Related: [docs/product/20-gap-analysis.md](../../product/20-gap-analysis.md)、[docs/product/21-roadmap.md](../../product/21-roadmap.md)、[docs/superpowers/plans/2026-09-29-autonomous-iteration-backlog.md](../plans/2026-09-29-autonomous-iteration-backlog.md)

## 1. 背景与产品判断

「代账专业可用」程序已于 2026-09-29 收口：主做账闭环、往来 L1–L3、账本包、备份恢复、打印/服务端 PDF、月末五步向导等均已落地，P0/P1 清零，旧自主迭代队列已关闭。

在此基线上，继续按 PRD 堆新业务域（OCR、移动端、AI、税局直连、完整 SaaS 多租户）**边际价值低、发散风险高**。下一阶段主轴定为：

> **代账吞吐第二曲线**：不扩新业务域，专治代账会计每天反复碰到的摩擦与资金/账簿可信度缝隙；用可独立验收的小切片自我迭代。

薄质量门禁嵌在每刀交付中，避免「越改越脆」。

## 2. 目标用户与成功标准

### 2.1 用户

| 角色 | 本阶段关切 |
|------|------------|
| 代账会计 / 做账员 | 多账套切换下接账、对账、月末、交账速度与少踩坑 |
| 审核员 / 财务负责人 | 结账前校验可信、往来与资金勾稽可解释 |
| 交付 / 产品 | 文档与代码一致；每刀可演示、可回滚 |

### 2.2 成功标准（本程序结束时）

1. **吞吐**：至少 3 个已落地的吞吐/可信度切片进入生产路径（见 §5 队列），且各有回归证据（单测和/或 E2E）。
2. **可信**：日记账↔凭证、往来对账单、辅助穿透三类「客户追问型」缺口至少关闭 2 类主路径。
3. **不回退**：关键路径（登录→录凭证→月结→三表→账本包）冒烟/既有 E2E 保持绿；质量仪表盘日期与数字刷新。
4. **叙事一致**：`docs/product/*` 与本规格队列状态同步；旧 roadmap 中已过时的「未做」表述清掉。
5. **边界清晰**：§4 Non-goals 全程未开工。

## 3. 方案选择（已拍板）

| 选项 | 结论 |
|------|------|
| A 质量债优先 | 不单独立项为程序主轴；仅作每刀门禁 + W0 薄启动 |
| **B 代账吞吐第二曲线** | **采用** |
| C 增值模块深化（薪资/OCR/申报） | 本阶段不做主轴；仅当 W1–W2 完成后按需挑 1 个「真影响交付」的边角 |

## 4. Non-goals（明确不做）

| 项 | 理由 |
|----|------|
| 税局直连 | 申报底稿已有；直连属另一产品线 |
| 工资条 / 员工自助 | 代账 PC 闭环非刚需 |
| 移动端 / AI 做账 | 依赖稳定 PC 主路径与数据质量，置后 |
| 完整 SaaS 多租户 / 计费 | institutions 保持品牌+骨架 |
| 按钮级权限全站铺开 | 角色-资源 + 账套授权已够用（Post-V1） |
| 独立收付款业务单据改造 | 往来仍以辅助核算 + 核销为主 |
| 重做月末向导 / 重做专业可用已交付能力 | 避免重复立项 |

## 6. 自主迭代作业方式

沿用已验证的节奏，文件落点与上轮一致：

1. **Propose**：每刀先写短 OpenSpec change 或 `docs/superpowers/plans/YYYY-MM-DD-<slice>.md`（目标/非目标/任务/验收）。  
2. **Apply**：最小 diff；禁止顺手大重构。  
3. **Verify**：相关单测 + 约定回归；失败先修再宣称完成。  
4. **Docs**：同步对应 `docs/product/*` 与本规格队列状态。  
5. **Archive / Commit / Push / PR**：一刀一提交叙事清晰；PR 描述含验收要点。

用户已授权全权自主推进；仅在以下情况停下来问人：

- 与 §4 Non-goals 冲突或需扩大范围；  
- 会计规则存在两种合规解释且无法从现有代码惯例推断；  
- 破坏性数据迁移无法幂等回滚。

## 7. 架构与改动边界

本程序是**产品切片组合**，不是新子系统。

| 层 | 约束 |
|----|------|
| 数据 | 优先扩展既有表（辅助查询、核销标记、config 开关）；新表须有 seed/patch 幂等 |
| API | 前缀保持 `/api`；复用 `Arap*`、`Journal*`、`Statement*Balance*`、`FixedAsset*`、`VoucherSettlementParams*` |
| UI | Element Plus 既有后台布局；不做营销落地页式改版 |
| 权限 | 不扩大到按钮级全站；新写接口沿用 `ProductRoles` / 账套管理员模式 |
| 测试 | 后端 JUnit；前端 Playwright 只加最小用例，不重写套件 |

### 错误处理（产品口径）

- 硬门槛失败：页面内联可行动提示（对齐月末向导 `silentError` 思路），避免仅全局 toast。  
- 软警告：保留可继续，但导出/对账单须能看见状态。  
- 配置变更：封存账套拒绝写入（与现网备份/参数页一致）。

## 8. 风险与缓解

| 风险 | 缓解 |
|------|------|
| 辅助穿透查询性能 | 先做筛选+分页；大账套加期间强制条件；必要时限流提示 |
| 红冲联动改坏日记账余额 | 事务内重算；单测覆盖生成凭证→红冲→余额；禁止半成功 |
| 文档与代码再度漂移 | W0 建立「合入即改分册」；收口刀再扫一遍 |
| 范围爬行到 OCR/权限大改造 | §4 硬挡；新需求进 Post-V2 列表不进本队列 |

## 10. 首刀建议（实施计划入口）

实施计划应先落地 **W0-1 + W0-3 文档门禁约定**（纯文档/流程，零运行时风险），紧接着 **W1-1 辅助穿透**（第一个有用户可感知价值的功能刀）。W0-2 质量仪表盘可与 W1-1 并行或紧随其后，以环境能否跑通测试为准。
