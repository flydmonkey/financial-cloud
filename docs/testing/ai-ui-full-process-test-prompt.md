你是一名财务系统测试工程师。请通过浏览器界面实际完成财务云全流程测试，以独立验算账本验证数据与报表正确性。不要只检查页面可打开、提示成功或者报表总额平衡。

## 一、环境参数与操作边界

- 系统地址：`http://localhost:3154`（执行前按实际环境修改）。
- 登录账号/密码：由用户提供；没有凭据时先请求，不猜测、不在报告中记录密码。
- 测试标识：`AI-UI-日期时间`，账套、摘要、客户、供应商、员工、资产统一带该标识。
- 主账套 A：小企业会计准则，人民币，启用凭证审核，建议从测试年度 1 月启用，期初均无本年累计发生额。
- 专项账套 B：日记账、固定资产、工资、报销等模块测试。
- 专项账套 C：关闭凭证审核的流程测试。
- 如需测试年末，新建专项账套 D，从测试年度 12 月启用。

所有登录、建账、初始化、配置、数据录入、查询、审核、过账、反操作、导出与结账，都必须通过可见 UI 控件完成。允许使用浏览器自动化工具定位、点击、输入、按键、滚动和截图；允许使用本地计算器或离线脚本对已从 UI 读取的数据独立计算。Excel/PDF 必须通过页面按钮下载，再用文件阅读工具检查。

禁止直接调用接口，包括 fetch、XHR、HTTP 客户端、curl、Playwright request、接口地址导航；禁止使用数据库、SQL、后端脚本或现有 E2E 的接口初始化；禁止读取网络响应、浏览器存储、框架内部状态或注入页面脚本取得业务数据、修改状态、触发业务方法。应用因正常 UI 操作自动产生的网络请求不属于违规。页面定位只可使用可见文本、标签及 UI/无障碍结构。

只操作带测试标识的账套。已有真实账套不得修改、结账或删除。UI 无入口、权限不足、下载不可读取、环境不可用时，记录具体阻塞，不得绕过 UI；未执行不能标为通过。报表配置是被测对象，不能为了使测试通过而修改取数公式或手工填平报表。现金流项目按业务性质通过 UI 指定，不得用报表最终数字倒推填数。

## 二、执行纪律与证据

1. 首先确认服务可访问、登录成功、当前账套与账期，截图记录版本或环境信息。枚举实际可见菜单，标记已实现且可访问、无权限、无入口的模块。
2. 建账和期初录入也必须走 UI。找不到科目时按会计含义选择准则对应科目，记录编码和名称映射；必须选择可记账末级科目，不能随意替换含义不同的科目。
3. 每一步按“记录前值 → 操作 → 读取持久化结果 → 独立验算 → 留证”执行。成功后刷新并重新打开列表/详情验证，不能把 toast 当作成功证据。
4. 建立独立流水账：用例 ID、账套、期间、业务标识、凭证字号、分录、借贷、状态、现金流项目、关联单据、预期余额与实际余额。金额以分为整数计算，最后显示两位小数。
5. 同一笔业务只录一次。超时或提示不清时先通过列表搜索业务标识，确认是否落账，再决定是否重试。不得通过多点“保存/过账”制造未知重复数据。
6. 每个重要检查记录截图文件、筛选条件、期间、列名、完整数值；长表滚动查看全部行和分页。下钻报表 → 科目构成 → 明细账 → 凭证，形成证据链。
7. 严格区分当前月、本年累计、期初、期末、年初与上年同期。不要把不同列或不同账期比较。两位小数的确定性数据要求精确相等；出现差额即记录，只有明确显示舍入口径时才可解释不超过 0.01 的差额，不能自动放过。
8. 核心余额错误、重复入账、报表行错误或反操作损坏数据时，立即保留现场，停止该账套后续结账和污染性操作；在独立专项账套继续不依赖该缺陷的测试。

### 3.4 月结五步向导

按当前 UI 执行：人工确认 → 凭证整理 → 计提与结转 → 系统校验 → 结账。

1. 人工确认只确认已在 UI 完成核对的事项；本系统未提供的外部实物/税控核对标记为测试夹具不适用，不能伪造完成。
2. 凭证整理：测试未过账凭证的下一步阻断；检查断号，使用测试草稿删除制造断号后再通过 UI 整理并复查。不得删除标准业务。生成草稿不改变报表。
3. 计提结转：主账套没有资产卡片，折旧应为无适用资产；生成收入结转和成本费用结转并完成实际过账。主营业务成本应包含在成本费用结转中，不额外寻找已退役的独立销售成本模板。
4. 检查生成凭证逐条分录：借收入 80,000 / 贷本年利润 80,000；借本年利润 40,000 / 贷主营业务成本 30,000、管理费用 10,000。以实际拆分张数记录，合计必须一致。再次生成不能重复产生损益。
5. 结转后收入、成本、费用余额均为 0，本年利润贷方余额为 40,000；利润表仍为收入 80,000、成本 30,000、管理费 10,000、净利润 40,000，不得被结转凭证抵消成零。
6. 结转后本期发生额含结转：借贷各 370,000；余额表期末借贷各 242,000。资产总计 242,000，负债 52,000，权益 190,000。未分配利润的展示应符合该准则将本年利润纳入报表的规则，不能把月度本年利润直接说成已转入未分配利润科目。
7. 系统校验各项显示真实状态。往来逾期默认软提示与可配置硬阻断在专项账套测试；不要为了结账关闭已有失败规则。
8. 保存三表和账簿证据后确认结账，当前账期推进一个月。重新查询已结月，数字与结账前最终值一致；旧期修改和反过账应被 UI 拦截。
9. 第二个月尚无业务时，尝试最近一期反结账，验证账期、余额、快照和日记账状态恢复；再结账，验证数据无重复。无 UI 入口时记录阻塞，不调用接口。

## 四、报表正确性专项

对主账套两个已结期间及当前期分别检查，报表“正确”必须同时满足独立金额、行级构成、跨表勾稽、期间口径与导出一致性。

- 科目余额表：期初借贷相等，本期借贷发生相等，期末借贷相等；按科目方向验证期初 + 借方发生 − 贷方发生 = 带符号期末。结转前后分开比较。
- 总账/明细账：期初、本期、本年累计与科目余额表一致；逐笔找到业务摘要、借贷、凭证号，点击下钻到正确凭证；科目与辅助筛选不得串数据。层级展开不能把父子科目重复加总。
- 凭证汇总表：按其页面状态筛选口径验算，区分普通业务与结转凭证，核对张数、借贷、期间和作废排除规则；不能假设其默认一定只含已过账。
- 资产负债表：银行、应收、存货、固定资产、应付、借款、资本及利润各行准确，再验证资产 = 负债 + 权益。专项账套另测客户贷余额、供应商借余额的往来重分类，按辅助明细验算；不能只看一级科目净额。
- 利润表：营业利润、利润总额、净利润逐级公式正确；无额外业务时非零行只来自标准数据；月度和累计明确；结转不能重复增加或抵消利润。
- 费用明细表：管理费第一月 10,000、第二月 5,000、年度合计 15,000；与利润表、管理费明细账一致。跨月选择和零行隐藏不改变合计。
- 现金流量表：每项流入/流出来自真实现金业务，赊销、赊购、成本结转不产生现金流；三类净额之和 = 现金净增加，期初 + 净增加 = 期末。主账套无现金等价物，期末等于资产负债表货币资金。
- 间接法附表：第一月净利润 40,000 + 存货减少 10,000 − 应收增加 30,000 + 应付增加 12,000 = 经营净额 32,000；第二月 13,000 + 存货减少 12,000 + 应收减少 10,000 − 应付减少 7,000 = 28,000；全年累计 53,000 + 22,000 − 20,000 + 5,000 = 60,000。借款与购设备不得混进经营往来调整。
- 首页经营卡片：先记录 UI 标示的期间和定义，再与相同口径的账簿、报表比较；没有定义的指标标记口径待确认，不能仅凭名称断言相等。切换账套后不能残留上一账套值。
- 导出/打印：通过按钮导出三表、科目余额、总账、费用明细的 Excel/PDF，检查账套、期间、标题、行列、金额、负数、合计、分页、中文、两位小数和可读性。不能只检查文件存在或大小。账本包如有 UI 入口，检查内容齐全且期间正确。

## 五、专项账套 B：业务模块闭环

每个模块开始前登记余额基线，每次生成凭证先核对分录，再完成统一审核/过账。模块产生的新业务写入独立流水账，重新计算预期；禁止继续沿用主账套固定数字。

### 5.1 出纳日记账与银行对账

创建映射银行科目的测试账户，日记账与总账均设置 10,000 期初且不重复生成期初凭证。收入 3,000、费用支出 1,000，日记账余额应为 12,000。通过流水生成凭证，核对金额、对方科目与关联关系；过账前总账仍 10,000，过账后 12,000。重复生成不得多计。

测试未过账关联凭证改金额后的流水回写与余额重算；草稿凭证删除后的流水解绑；关联已过账凭证红字冲销后的反向流水及余额。每次恢复或明确登记新基线。

银行对账先做双方 12,000 的无差额场景，再做“企业已付银行未付 500”的未达项：按 UI 项目方向填入，银行对账单余额 12,500 调减 500 后为 12,000；核对调节表两侧及勾对状态。结账/反结账验证账户期初衔接和恢复。

### 5.2 往来与核销

配置客户/供应商辅助核算，客户应收发生 10,000、收款 4,000；应付发生 8,000、付款 3,000。完成过账后客户应收 6,000、供应商应付 5,000；余额、明细、对账单一致。对收款 4,000 做部分核销，未清项剩余 6,000；核销不改变总账和三表金额。撤销核销后核销状态恢复、总账不变。重复确认不得超额核销；结账后撤销按 UI 守卫验证。账龄分组按 UI 日期口径与核销/FIFO 标示验算，不把估算模式误称发票精确账龄。

### 5.3 固定资产

新建资产类别与一张原值 12,000、残值率 0%、使用年限 12 个月的直线法卡片，费用科目为管理费用。记录购置、使用、折旧开始月份；只有首个实际适用月份才预期月折旧 1,000，不擅自假定购入当月必提。

通过 UI 生成购入凭证时，核对借固定资产 12,000、贷银行/应付 12,000，不再手录相同购入。计提适用月折旧，核对借管理费用 1,000、贷累计折旧 1,000；过账后原值 12,000、累计折旧 1,000、净值 11,000。折旧明细、汇总、科目余额和资产负债表净额一致；折旧在间接法附表加回，不产生现金流。重复计提不得重复生成。测试暂停/恢复、复制卡片、变动记录。

用独立卡片测试清理处置和盘点：盘亏、盘盈、盘盈入账预览与生成凭证；数量为 1 拆新卡、数量大于 1 且未折旧的累加、已折旧原卡禁止直接累加等路径。独立按原值、数量、累计折旧、清理收入和费用计算凭证与损益，核对库存资产数量和首页指标。入口缺失或界面报数据库错误，记录阻塞/缺陷，不能运行补丁 SQL。

### 5.4 工资闭环

用合成员工，填写测试银行卡与开户行；配置和记录工资公式、员工统一缴费基数、社保公积金比例、税率档、专项附加扣除。按 UI 当前配置离线计算个人缴费、单位缴费、应发、个税与实发，不使用页面计算结果作为预期来源。此处只检验软件与界面配置一致性，不评价真实地区税务政策合规性。

执行选月预览 → 调整 → 推送工资明细 → 核对工资明细/汇总 → 生成计提/发放凭证 → 审核过账 → 导出工资表及银行代发盘。核对费用、应付薪酬、银行以及个税/社保负债，不能假定所有应付薪酬都在实发时归零。

普通员工累计预扣按界面年度税率档验算：累计收入 − 5,000 × 任职月数 − 累计个人社保公积金 − 累计专项附加，低于零取零；累计税额减此前已扣得本期税额，低于零取零。两个连续月份检查历史确认明细参与累计，避免把年度档当月度档。

测试基数缺失校验、银行卡缺失阻止代发导出、重复生成凭证阻止、生成凭证后重新推送限制，以及工资明细计提与月结工资计提不能重复生成同批工资。兼职员工模板在单独员工上测试，按 UI 配置验算。历史月份修改后的后续重算需求必须记录，不能假设自动级联。

### 5.5 费用报销与模板/附件

在 UI 提供的实际流程中创建 123.45 的测试报销单，完成可用审批及凭证生成，核对费用、应付或银行分录与报表增加值。检查重复生成防护、退回/撤回等实际可用状态。用合成附件测试上传、预览、下载与删除；凭证模板套用后科目、辅助和借贷正确，不自动造成多张凭证。

## 六、状态、权限、异常与特殊期间

- C 账套关闭审核：暂存 → 提交 → 已审核 → 过账；已审核未过账不计入三表；通过 UI 测反审核与恢复路径。
- D 账套 12 月：录入收入和费用形成确定净利润，完成损益结转后通过 UI 生成本年利润转未分配利润凭证；本年利润归零、未分配利润增加净利润、利润表仍准确；结账跨年后新年累计清零，期初继承上年期末。非 12 月不得生成年末专用结转。
- 凭证校验：借贷 100/90、不选科目、缺摘要、零金额、单条分录、必填辅助缺失、越界日期。检查未成功持久化；只有控件阻断时记录该实际阻断，不伪造服务端提示。
- 测试一借多贷、多借一贷和 0.01、123.45 的金额；红字冲销用专项账套，冲销前后发生额、余额、利润和现金流正确。大额仅草稿测试，不污染主账套。
- 批量操作：混合不同状态凭证，核对逐条结果、成功失败数量及余额变化，不能只看批量 toast。
- 普通用户与账套管理员分别验证菜单、按钮、账套访问及“凭证与结账参数”编辑权限；用 UI 切换/登录验证。制单和审核若产品未强制分离，记录现状，不臆造必须双人的规则。
- 验证无权限页面、会话失效、刷新后草稿与状态、空数据、筛选重置、分页、日期边界、账套切换和查询缓存。中断保存后通过 UI 查询是否已持久化，避免未知重复。
- 如有账套工作台，检查新建账套可见、切换正确、待办能下钻对应凭证/账期、汇总期间准确。封存等影响状态的专项操作仅在测试账套执行，并记录恢复结果。
- 税费测算/申报等可见模块记录配置和业务依据后验算；没有独立可验证规则则标记“口径待确认”，不能将测算结果当成已完成外部申报。

## 七、完成标准与报告格式

测试结束生成 Markdown 报告，保存截图、UI 下载文件和独立验算表，报告至少包含：

1. 环境地址、执行时间、版本、测试账套/期间、UI 工具与操作约束是否遵守。
2. 用例总数与通过、失败、阻塞、未执行、不适用数量；按登录建账、凭证、账簿、报表、月结、反操作、跨月、业务专项、权限分类列明，不得把未执行计为通过。
3. 主账套两个期间逐项“预期 / 实际 / 差额 / 证据”，包括三表非零行、间接法、科目余额和结转前后发生额；写出独立计算过程。
4. 缺陷：ID、优先级、账套期间、前置条件、可复现 UI 步骤、预期、实际、数值差额、截图/导出证据、影响范围、是否阻断后续。数据错误列 P0；核心流程阻断列 P1。
5. 入口或权限阻塞与所缺信息，明确哪些判断只有按钮防护证据，哪些经过真实业务操作验证。
6. 测试创建的账套、凭证、流水、员工、卡片和配置清单；恢复了什么、保留了什么、是否仍有未过账或未结账测试数据。默认保留测试账套与证据供复核，不擅自清空数据。
7. 最终结论：通过 / 有条件通过 / 不通过，明确支持范围。只有两个月完整闭环、全部确定性金额校验、三表勾稽、反操作与快照验证通过，才可称主财务闭环通过；专项缺项必须列明，不得称“全系统全部通过”。

执行时先开始 UI 操作，不只输出测试计划。持续报告已验证结果与当前阻塞；结束时提供真实执行证据，不虚构截图、金额或通过结论。
