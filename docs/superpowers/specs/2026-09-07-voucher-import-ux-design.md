# 凭证导入导出体验增强设计

日期：2026-09-07  
状态：已实现（待手工冒烟）  
关联：OpenSpec `voucher-import-export`（已落地基础导入导出）

## 目标

在现有「统一 Excel 往返 + 全量筛选导出 + 暂存导入」基础上：

1. 整理 Excel 观感与可填性（列契约不变，版式变细）。
2. 字号冲突时由用户选择覆盖 / 跳过 / 取消（覆盖范围：未过账）。
3. 列表「更多」支持将勾选的**暂存**凭证批量提交为**待审核**（复用现有 submit 语义）。

## 已锁定产品决策

| 项 | 选择 |
|----|------|
| 覆盖范围 | **未过账**可覆盖：`draft` / `reviewing` / `completed` 且 `senderId` 为空；**已过账不可覆盖** |
| 提交审核入口 | 「更多」菜单 |
| Excel 列契约 | 保持：凭证日期、凭证字头、凭证字号、附单据数、备注、摘要、科目编码、借方金额、贷方金额 |

## 范围

**纳入**

- 导入模板与导出工作簿的样式、说明 Sheet、列宽与数字/日期格式
- 导入冲突预检 + 二次确认导入（`conflictMode`）
- 覆盖更新未过账凭证分录；跳过冲突组；取消整次
- 列表「更多 → 提交审核」批量提交暂存

**不纳入**

- 旧版「凭证字 / 账套ID」导出格式兼容写入（仍拒绝并提示重导）
- 辅助核算 / 现金流量列往返
- 覆盖已过账凭证
- 导入直接过账
- 改审核/过账状态机规则（提交仍走现有 `submitBatch`）

## 1. Excel 格式整理

### 列契约（不变）

与现网 `VOUCHER_IO_HEADERS` 一致，一行一分录；同一凭证续行可留空抬头字段。

### 版式

| 项 | 约定 |
|----|------|
| Sheet「填写说明」 | 说明列含义、续行规则、日期格式 `yyyy-MM-dd`、科目须为账套内编码、字号冲突时前端可选覆盖/跳过 |
| Sheet「凭证」 | 表头加粗 + 浅底色；冻结首行；日期列文本/日期格式；金额列两位小数；合理固定列宽（不再仅 autoSize 显得过宽/过窄） |
| 模板示例行 | 保留 1 组借贷示例，浅色底提示「示例可删」 |
| 导出 | 与模板同构列与样式；不含说明页也可，但数据 Sheet 样式与模板一致 |

## 2. 导入冲突：覆盖 / 跳过 / 取消

### 冲突定义

在**当前账套**内，按导入组解析出的 `voucherDate` 得到年/月，与 `wordHead` + `wordNum` 匹配已有凭证：

- 命中且 **未过账** → 冲突候选（可覆盖或跳过）
- 命中且 **已过账** → 不可覆盖；该组失败原因明确（与「跳过」区分）
- 未命中 → 新建（仍为 draft）

空字号仍走自动分配，不进入冲突流程。

### 交互

1. 用户上传文件后，前端先调用导入（或专用预检）；若存在可决策冲突且未带 `conflictMode`，后端返回特殊结果：`code` 成功或约定业务码 + `data.conflicts[]`（字号、现状态、Excel 行号），**不写库**。
2. 前端弹窗展示冲突列表，三按钮：
   - **覆盖**：对未过账冲突组执行更新；非冲突组新建；已过账冲突组记失败
   - **跳过**：冲突组不导入；其余新建
   - **取消**：关闭，不请求写库
3. 再次请求携带 `conflictMode=overwrite|skip`（`multipart` 附加字段或 query）。

推荐实现：同一 `POST /voucher/import`，表单字段 `conflictMode` 可选；缺省且检测到未过账冲突时返回 `needsConflictDecision=true` + conflicts，不落库。

### 覆盖语义

- 定位到未过账凭证 id，清空审核/过账/主管字段不强制（过账本就为空）；分录替换为 Excel 内容。
- 状态：覆盖后落为 **draft**（便于用户再提交审核），与「导入一律暂存」一致；不因覆盖直接变 reviewing。
- 校验：借贷平衡、科目编码、开放期间——与新建相同；失败则该组失败，不影响其他组。

### 跳过 / 取消

- 跳过：冲突组不写入；统计 `skipped`
- 取消：前端不发起二次请求

## 3. 批量提交审核

- 「更多」增加「提交审核」，`disabled` 当未勾选。
- 仅对勾选中状态为 `draft` 的凭证调用现有 `POST /voucher/submit/{ids}`（已有 `submitBatch`）。
- 账套开启审核 → `reviewing`（待审核）；关闭审核 → 现有逻辑可直接 `completed`（产品文案仍可用「提交审核」，结果提示沿用接口 message）。
- 无可用暂存时 toast 提示。

## 影响面

| 层 | 变更 |
|----|------|
| 后端 | `VoucherService` 导出/模板样式；`importFromExcel` 增加冲突预检与 `conflictMode`；结果 VO 增加 conflicts / skipped / needsConflictDecision |
| 前端 | 导入结果与冲突弹窗；`importVouchers` 传 `conflictMode`；`voucher-index`「更多 → 提交审核」 |
| API | `POST /voucher/import` 兼容扩展字段；提交审核无新路径 |

## 验收要点

1. 新模板有说明 Sheet、表头样式与金额/日期格式；导出数据 Sheet 观感一致。  
2. 导入未过账同字号 → 弹窗三选一；覆盖后列表为暂存且分录已换；跳过则原凭证不变且该组未新建；取消无变更。  
3. 已过账同字号 → 不可覆盖，失败原因可读。  
4. 「更多 → 提交审核」可将勾选暂存批量提交；非暂存被忽略并有反馈。

## 非目标重申

不支持旧导出列写入；不覆盖已过账；导入不直接审核/过账。
