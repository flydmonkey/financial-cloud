# 全模块账套隔离检查（2026-10-01）

## 修复阶段更正（2026-10-02）

原审计把工资公式视为全局数据，判断有误。数据库和初始化 DDL 均含必填 book_id，Java 模型漏了字段；已按账套配置修复并补充回归。个税税率仍为全局数据。修复验收另见 book-isolation-fix-verification-2026-10-02.md。

## 结论与范围

当前不能认为系统已实现完整的账套隔离。除凭证、固定资产、工资、出纳的既有缺陷外，本轮发现更优先的账套权限绕过，以及科目、辅助核算、部门、配置、报表配置和文件访问问题。

扫描清单包含 84 个控制器/认证端点类：71 个启用，13 个控制器的 `@RestController` 已注释。启用类包含 67 个业务控制器和 4 个认证端点。逐类清单见 [控制器清单](all-module-isolation-controller-inventory.csv)。这是全模块代码审查加重点接口实测，不代表每个接口、每种参数组合均已动态验证。

动态验证只使用 `financial_cloud_e2e_20261001` 隔离数据库、两个假账套和专用测试用户，没有修改正式数据库。本轮诊断脚本完成 26 次观察；脚本执行成功表示成功采集结果，不表示安全检查通过。原四模块的证据见 [四模块报告](book-isolation-audit-2026-10-01.md)。本轮未修改业务实现。

## 已实测确认的问题

### P0：未授权账套切换及自行提权

创建只读用户，仅授予账套 A 的 `ROLE_VIEWER`；其账套列表只有 A。

1. 调用 `/api/users/switchBook/{B}` 返回成功，当前账套变为未授权的 B，用户的可访问账套列表仍只有 A。
2. 调用旧接口 `/api/permissions/permissionBook/add`，指定自己的用户 ID、B 和 `ROLE_ADMINISTRATORS`，返回成功。
3. 随后可访问账套列表包含 A、B，读取 B 的成员列表成功。自行授权之前，该成员接口和 B 的备份接口均拒绝访问。

`UserInfoController` 的切换入口没有验证目标账套成员资格；`PermissionBookController` 的旧授权入口没有验证调用者对目标账套的管理权限。新版成员管理自身的权限检查无法阻止旧入口绕过。`PermissionInterceptor` 认证成功并加载权限，并不自动校验所有业务接口的账套归属。

### P1：其他已确认的越界读取

在当前账套 A 下，以 B 的参数或记录 ID 查询，以下返回成功并返回 B 的数据：

| 模块 | 实测入口/对象 | 结果 |
| --- | --- | --- |
| 会计科目 | 科目列表、科目树、科目详情的客户端 bookId | 返回 B 科目；科目树返回 70 个根节点 |
| 辅助核算 | 外账套辅助项目 ID | 返回 B 项目 |
| 部门 | 外账套部门 ID | 返回 B 部门；仅授权 A 的只读用户也可读取 |
| 系统配置 | 外账套 configId | 返回 B 配置 |
| 通用文件 | 他人 fileStorage ID | 返回测试文件内容；仅授权 A 的只读用户也可读取 |

通用文件表没有 `book_id`，因此该问题属于文件对象/所属关系授权缺失。凭证或报销附件专用入口的归属检查不能替代通用文件入口的授权。

### P1：报表配置跨账套写入及搬迁

两项均已用只读数据库查询确认持久化结果，不能仅通过接口返回值判断：

- 现金流量期初配置：在 A 调用保存接口，嵌套项目 ID 指向 B；B 的 `balance` 被改为 `77.00`，归属仍是 B。
- 资产负债表项目配置：在 A 保存 B 的项目 ID；项目名称变为 `cross-book-config-audit`，`book_id` 从 B 改成 A。

前者批量更新没有验证嵌套记录归属；后者覆盖 DTO 的 bookId，却没有先验证原记录归属。将当前账套写入 DTO 不能阻止外账套记录被修改或搬迁。

## 修复顺序和验收

1. 先关闭权限根因：切换时验证目标账套成员资格，旧授权/角色成员入口验证目标账套管理权限，刷新及撤权处理当前账套资格。
2. 统一所有对象读写的原记录归属校验，阻止更新搬迁、外部 ID、混合批量 ID 和嵌套关联 ID；同步保护文件对象。
3. 补齐科目、辅助、部门、初始化余额、配置及报表配置；原四模块修复仍在待做清单中。
4. 使用至少两个账套和仅授权 A 的用户回归：B 的读取/写入/删除/状态变更/关联引用均拒绝，拒绝后 B 的归属、余额、配置及权限不变；合法切换和明确的全局模板访问继续可用。
