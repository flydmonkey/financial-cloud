# 全模块账套隔离修复验收（2026-10-02）

本次落实两份 2026-10-01 审计报告确认的问题。静态审计范围为 84 个控制器类（71 个启用、13 个未启用）；动态验收覆盖关键隔离链路及正常业务流程，不代表每个接口都已逐一实测。

## 修复内容

- 新增 `BookOwnershipGuard`，校验原记录所属账套、客户端账套参数、关联对象、嵌套对象和完整批量 ID；校验通过后绑定当前账套。已有跨账套关联也会被拒绝，不能通过省略请求字段绕过检查。
- 凭证、模板、资产及分类、员工、工资、暂存工资、个税抵扣、出纳账户/流水，以及科目、辅助核算、部门、期初余额、报表配置、报销、往来核销等入口接入归属检查。个税抵扣导入清理历史记录补齐账套条件；部门、用户导入先校验整批对象。
- 切换账套先检查有效授权；请求及会话刷新检查授权是否仍有效。旧账套授权、角色成员入口检查目标账套管理员资格，不能自行授权或跨账套管理。当前用户返回当前会话账套，避免另一会话切换覆盖本会话状态。
- 系统配置、现金流期初、社保公积金、工资公式及报表配置维护检查管理员权限。固定的四个产品角色禁止修改/删除；自定义角色代码不能伪装产品管理员权限。
- 公共会计制度模板允许明确指定制度 ID 的读取；账套模板默认限定当前账套。只读用户及公共模板读取不触发隐式模板更新。
- 通用文件访问校验绑定的凭证/报销附件账套；批量操作先验证全部文件。已绑定文件不能经通用删除入口删除。未绑定文件按上传者归属管理。

## 数据边界与审计更正

工资公式原审计误归为全局配置。初始化 DDL 和实际测试库都有必填 `config_salary_formula.book_id`，Java 模型遗漏了映射；本次补齐模型、DTO、列表条件及归属检查，无须新增列或迁移。

个税税率、会计制度及标准模板是共享数据，采用现有产品账套管理员维护权限；只读用户不能维护。科目现金流映射同时包含制度模板和账套副本，账套入口已有当前账套条件。共享用户身份的维护须具备受影响各有效账套的管理员资格；添加账套成员使用目标账套管理员授权入口，不需要修改共享身份。
