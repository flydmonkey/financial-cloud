# 21 · 迭代路线建议

> 目标：在**代码现状**与外部 PRD 之间找可交付路径。  
> 主轴对齐 OpenSpec「代账商业化总规划」：`交付包 → 打印与吞吐 → 资金往来 → 周边卫生`。  
> 同时映射 PRD 的 V1.1（税务）/ V1.2（薪酬票据）/ V1.3（移动+AI）。

| 项 | 来源 | 状态 |

### S0 · 交付包（当前 OpenSpec 首期）

**权威提案**：[openspec/changes/daizhang-commercial-plan](../../openspec/changes/daizhang-commercial-plan/proposal.md)

**产品文档动作**：实现后更新 [05-statement.md](05-statement.md) 与差距清单 7.6。

### S1 · 打印与吞吐

| 项 | 说明 | 对接缺口 |
|----|------|----------|
| 经典凭证打印接入 | 将 `voucherPrintHtml` / classic HTML 接到 `onPrint` | [03](03-voucher.md) |

| 报表 PDF / 打印 | 三表与账簿 | 差距 7.4 |
| （可选）建账/期初录入提速 | 代账接手吞吐 | commercial-plan S2 |

### S2 · 资金往来（对齐 PRD 最大缺口 + commercial-plan S3 前半）

**L1+L2 已落地**（`openspec/changes/arap-l1-l2`）：

1. 往来单位应收/应付**余额表 + 明细**（按客户/供应商辅助）  
2. **对账单**导出（Excel）  
3. **账龄**分段（30/60/90/180+，FIFO 估算）  
4. 结账校验接入真实应收应付/逾期警告（不硬阻断）  

后续再做：核销 L3、银行调节、辅助余额穿透查询。

### S3 · 周边卫生

| 项 | 说明 |
|----|------|
| 账套手动备份 / 恢复 | P0 安全项；可与账本包区分（全量数据 vs 报表包） |
| 业务操作审计 + IP | 凭证/结账/权限变更 |
| 往期锁定补齐、制单≠审核 | 合规 |
| 凭证附件 | 影像绑定 |
| 首页待办 | 待审/折旧/结账 |
| 资产盘点、多栏账等 | P2，按客户声音排序 |

## 3. 与外部 PRD 版本规划的映射

| PRD 版本 | PRD 主题 | 相对本仓库的建议 |
|----------|----------|------------------|
| **V1.0** | 八大模块全覆盖 | 文本上宣称「已完成」**不成立**；应以本目录 as-built + [20-gap-analysis](20-gap-analysis.md) 重写验收标准。往来+备份未完成前不宜称 PRD V1.0 全覆盖。 |
| **V1.1** | 税费测算、申报表、税负预警 | **尚未开始**。依赖科目与利润表数据已具备；建议排在往来与交付包之后，避免并行铺太大。Non-goal 仍含「税局直连」（与 commercial-plan 一致）。 |
| **V1.2** | 薪酬 + 票据 + 报销 | **薪酬大半已有**（分册 09）→ PRD 应改为「增强」而非「新增」。票据归集、费用报销仍为净新增，可跟在 V1.1 或与附件能力一起做。 |
| **V1.3** | 移动端 + AI 做账 + 消息预警 | 依赖 PC 闭环与待办/往来数据；预警可先做站内待办（S3），小程序与 AI 识别置后。 |
| **长期** | 税局/银行/进销存 | 与 OpenSpec non-goals 一致，保持储备，不进近端切片。 |
