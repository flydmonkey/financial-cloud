# 代账吞吐 Post-V2 · 产品设计规格

> Date: 2026-09-29  
> Status: approved under prior full authorization（接续吞吐 V2；用户「继续迭代」）  
> Related: [吞吐 V2](2026-09-29-daizhang-throughput-v2-design.md)、[backlog](../plans/2026-09-29-throughput-v2-backlog.md)

## 1. 背景

吞吐 V2（W0–W4）已收口。剩余高频摩擦中，**W2-2 过账后改证路径**仍是代账日常误操作点：列表「修改」可进编辑态，分录格仍可点，但保存被静默禁用；后端仅返回「当前不允许修改」。

本程序不扩新业务域，只收口该路径 + 文档。

## 2. 目标与成功标准

1. 已过账凭证在编辑页呈现只读，并给出可行动提示（反过账 / 红字冲销）。
2. 列表「修改」对已过账凭证走只读查看（与「查看」一致的只读路径，或带引导）。
3. 后端修改拒绝文案可区分：已过账 / 已作废 / 已结账期间。
4. 有前端单元测试 + 相关后端断言；文档 03/08 同步。

## 3. Non-goals

- 过账后直接改分录并自动回写账簿（禁止）
- 按钮级权限全站铺开
- TypeScript / ESLint 存量清零（仍质量债）
- 银行余额调节 / 税费向导增强

## 4. 切片

| ID | 切片 | 验收 |
|----|------|------|
| P1 | 编辑页已过账只读 + 引导条 + 反过账/红冲入口 | UI + `voucherWorkspace` 测试 |
| P2 | 列表「修改」对已过账强制 `readonly` | 路由 query |
| P3 | `VoucherService.update` 拒绝原因产品化 | 单测或现有测试补断言 |
| P4 | 文档收口 | 03 / 08 / backlog Post-V2 勾完 W2-2 |

## 5. 决策

| 题 | 决定 |
|----|------|
| 改已过账的合法路径 | 反过账后改 **或** 红字冲销；不提供第三轨 |
| 已审核未过账 | 仍仅草稿可改（既有前端门禁）；本刀不扩审核态可改 |
| 分支 | `cursor/post-v2-voucher-edit-path-9a0a`，独立 PR |
