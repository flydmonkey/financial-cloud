## 缺陷

### BUG-TZ-DATE（P0）

- **前置**：账套开放账期 2026-01，凭证日期 UI 显示 `2026年01月01日`
- **步骤**：新增凭证 → 日期为当期首日 → 暂存
- **预期**：允许暂存
- **实际**：`已结账期间不允许新增或修改凭证（当前开放账期 2026-01）`
- **对照**：改为 `2026-01-15` 后暂存成功
- **推测**：`2026-01-01 00:00:00+08` 按 UTC 格式化成 `2025-12`

### BUG-CF-UI-SIGN（P1）

- 指定抽屉保存时，前端用 `difference(debit-credit) + signed(cashFlowBalance)` 校验平衡；`direction=2` 的流入项需填**负金额**才能保存。
- 保存后现金流量表「销售商品收到的现金」等显示 **-50,000**，经营净额 **-42,000**（且 V04 反操作后「支付其他」丢失为 0）。
- e2e API 指定使用正数金额；UI 与报表/API 口径不一致，易导致报表符号错误。

### OBS-5602-LEAF

`5602 管理费用` 非末级，必须选叶子（本测用 `5602.01`）。

### OBS-UNAUDIT-TO-REVIEWING

已过账 → 反过账（待过账）→ 反审核后状态变为「审核中」而非「暂存」，必须再「撤回审核后修改」才能编辑。

### OBS-CARRY-STALE-POINTER

删除已生成的结转凭证后，`settlement_carryforward.voucher_id` 仍指向已删 ID，向导显示「已生成未过账」且无法再生成。本测用夹具修复删除陈旧行后重新生成（非业务录入）。产品应在删凭证时清理结转指针，或提供 UI 清除。
