# 账务可信验收包

本包用于开发验收和会计复核。自动化通过不等于会计已签字，也不表示税务申报或正式生产交付已经验收。

## 独立手算基准

输入与固定答案见 [accounting-reference-case.json](accounting-reference-case.json)。金额为合成测试数据，不计算税费。账套启用 2025-11，期初银行借方 100,000、实收资本贷方 100,000，其他为零。借方余额记正、贷方余额记负。预期金额不从系统报表模板、接口返回值或后端规则生成。

| 业务 | 借方 | 贷方 | 金额 |
|---|---|---|---:|
| 11 月赊销 | 应收账款 | 主营业务收入 | 20,000 |
| 收款 | 银行 | 应收账款 | 12,000 |
| 赊购材料 | 原材料 | 应付账款 | 10,000 |
| 付款 | 应付账款 | 银行 | 6,000 |
| 买资产 | 固定资产 | 银行 | 24,000 |
| 计提折旧 | 管理费用 | 累计折旧 | 1,000 |
| 计提工资 | 管理费用 | 应付职工薪酬 | 3,000 |
| 发工资 | 应付职工薪酬 | 银行 | 3,000 |
| 管理支出 | 管理费用 | 银行 | 2,000 |
| 确认成本 | 主营业务成本 | 原材料 | 4,000 |

11 月：银行 = 100,000 + 12,000 − 6,000 − 24,000 − 3,000 − 2,000 = **77,000**；应收 **8,000**，存货 **6,000**，资产净值 **23,000**，应付 **4,000**，工资余额 **0**。

利润 = 20,000 − 4,000 − 1,000 − 3,000 − 2,000 = **10,000**。资产 = 77,000 + 8,000 + 6,000 + 23,000 = **114,000**；负债及权益 = 4,000 + 100,000 + 10,000 = **114,000**。

现金流：经营 = 12,000 − 6,000 − 3,000 − 2,000 = **1,000**；投资 = **−24,000**；筹资 **0**；净变动 **−23,000**；期末 **77,000**。

更正案例：误计工资 200（借管理费用、贷应付职工薪酬），过账后全额红冲，原分录借贷均为 −200。两张凭证合计影响为零；保留原凭证和红冲凭证关联，不能靠删除原凭证使结果正确。

11 月结账→12 月无新业务时反结账→重新结账，以上数字均不变。12 月收应收 8,000、付应付 4,000、支付管理费用 1,000：银行 **80,000**、往来余额 **0**、当月利润 **−1,000**、年度累计 **9,000**。资产 = 80,000 + 6,000 + 23,000 = **109,000**。12 月年末结转后本年利润归零、未分配利润贷方 **9,000**；2026-01 银行期初 **80,000**。

## 场景覆盖与证据性质

| 场景 | 自动验证依据 | 会计人工复核 |
|---|---|---|
| 期初、往来、资产及薪资分录、三表 | 新增 independent-accounting-reference 用固定预期验证 | 按上表逐笔核对，无需读取系统取数规则 |
| 红冲 | 新参考案例全额负数凭证，金额影响为零 | 原凭证、红冲关联和账簿留痕 |
| 跨月、反结账、年末 | 新参考案例固定 11→12→1 月 | 期初承接、当月/累计口径、重新结账金额 |
| 客户供应商辅助与核销 | arap、arap-writeoff 既有模块回归 | 辅助单位余额、对账单和核销匹配；参考分录不替代辅助档案验收 |
| 资产卡片与折旧生成 | 新增 fixed-asset-accounting-reference：原值 60,000、残值率 5%、60 个月，月折旧固定 950；购入/折旧凭证与重复计提 | 核对卡片、凭证和报表；主参考案例中的资产使用手工分录，两类证据分别验证 |
| 薪资计算与凭证生成 | payroll-smb-regression 既有模块回归 | 算薪输入、扣款与计提/发放凭证一致；参考案例使用手工工资分录 |
| 导出交付 | report-export、monthly-books-pack 既有回归 | 对同一期 PDF、Excel、账本包与页面逐项核对 |

## 执行

后端必须显式连接 `financial_cloud_e2e_<suffix>`，自动备份关闭。终端设置同名 `FC_DB_NAME`、`FC_DB_HOST`、`FC_DB_PORT`、`E2E_API_URL` 与 `E2E_BASE_URL`，然后在前端目录执行 `npm run test:acceptance:accounting`。该命令会清理隔离库账套，不用于真实业务数据。各独立套件分别重置，不并发运行。固定答案用例缺少科目或断言不成立必须失败；运行器将跳过也计为验收失败。

工具保存每组 JSON、日志和汇总到 `.e2e-run/accounting-acceptance/<时间戳-运行ID>`，每次执行使用独立目录，避免旧结果混入。源码组件页面测试需 Vite；使用生产前端时同时设置 `E2E_COMPONENT_BASE_URL` 指向同一后端的 Vite 服务。既有模块用例作为补充证据，不把同源勾稽等同于独立手算。

候选发布核验见 [证据协议与只读入口](release-candidate-evidence.md)。验收运行器将保存测试前后源码、可获取产物、声明环境及原始报告哈希；这些采集信息不证明服务实际连接的库和运行产物，仍须技术复核的运行绑定。核验器分别检查完整会计与账套隔离范围、候选身份、实际 CI、真实月试账签字、问题台账及独立实例恢复；缺任一必需条件会输出阻塞清单。其 fixture 测试可单独完成，不替代本包真实业务验收。

第五轮已将新增证据工具、SQL 离线边界及真实薪资事务 IT 配置为 PR/push 必需检查，profile 更新为 version 2。本地 220 项离线检查与 21 项 MySQL 9.4.0 真实事务测试通过，详见 [第五轮记录](self-iteration-05-2026-10-03.md)。本轮未重跑本包完整会计及账套隔离验收，新候选远端 CI、实际生产运行绑定与人工签字仍待验证。
