# 便携账套备份 v2

新导出的手工备份、定时备份和覆盖前预备份均为 v2：包含账套业务表及有效凭证、报销附件引用的文件内容。备份不包含用户密码、授权关系、会话、全局模板或完整实例配置，不替代服务器和数据库的整体灾备。

## 使用

1. 由账套管理员在账套列表导出备份，妥善保存 ZIP。包中包含业务与附件敏感信息，应按账务资料保管。
2. 在另一实例先完成初始化、准则及基础模板安装，并建立一个供管理员登录的空白账套。登录后上传 ZIP，默认恢复为新账套；无需原账套或原文件仍存在。
3. 切换至恢复账套，核对账期、凭证数量、科目余额、三表与附件下载。恢复账套的新文件 ID 与原文件独立；人员和授权按现有恢复规则重新配置。
4. 覆盖恢复仍需目标账套管理权限和确认短语「覆盖恢复」，并先自动落盘预备份。建议先验证克隆恢复结果再使用覆盖恢复。

## 格式与兼容

ZIP 包含 `manifest.json`、`data/<table>.jsonl` 和 `files/<序号>.bin`。manifest 的 `formatVersion` 为 2；表声明含行数与 SHA-256；`files` 声明含原文件 ID、包内路径、字节数、SHA-256、文件名、类型与类别。恢复仅使用白名单文件元信息，重建新的文件记录和附件关联。

旧 v1 包继续支持同实例恢复：所有来源账套的管理员权限必须可验证，原附件文件必须存在。v1 不含附件内容，无法通过本次升级为已经丢失的附件补回内容。新 v2 包不能由旧 v1 服务恢复；回滚应用前须保留 v2 恢复能力或重新规划迁移。

## 完整性与限制

- 导出遇到缺失文件、无文件引用或跨账套共享的错误引用时失败，不提供不完整的成功备份。
- 恢复拒绝内容校验失败、缺失或重复文件声明、未知表、重复主键、未声明 ZIP 项、目录及异常路径；在创建账套或覆盖前完成包校验。
- 解压限制：单项 32 MiB、总计 128 MiB、最多 10,000 项；导出遵循同样限制。HTTP 备份上传上限 132 MiB，请求上限 136 MiB。凭证/报销单个附件仍由业务服务限制为 10 MiB。
- 恢复文件与业务表在同一数据库事务中写入，失败回滚。历史人员引用不继承为新实例授权。
- 超过限制的账套需要制定更大规模的备份方案；本格式仍在内存中生成和校验，不适用于无限增长的附件库。

## 验收证据

单测覆盖包内恢复无源查询、缺失和损坏文件、v1 来源权限、ZIP 重复路径与大小/数量限制。隔离端到端测试使用超过 4 MiB 的不可压缩附件，检查实际上传与恢复、损坏拒绝不创建账套、导出审计；删除源文件并清空原账套业务后建立空白接收账套，再检查包内恢复、凭证余额报表一致和附件逐字节一致。账套隔离套件另行检查删除恢复附件不影响来源及覆盖预备份。尚未在真实部署的第二台服务器演练。

运行入口：`npm run test:acceptance:accounting`，必须先配置隔离库与对应后端地址，详见 [会计验收](accounting-acceptance.md)。上线前由负责人员在实际候选版本和目标环境重做恢复演练，并完成 [会计试账签字](accountant-month-pilot.md)。
