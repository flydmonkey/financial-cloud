# 综合所得累计预扣（SMB 最小纠偏）设计

日期：2026-09-05  
状态：待实现  
范围：薪资模块普通工资个税由「按月应税套税率」改为「综合所得累计预扣法」最小闭环

## 背景

当前 `EmployeeSalaryTempService.calculatePersonalTax` 对普通员工把**当月** `taxableWages` 直接套用 `config_personal_tax`（type=0）税率档，且应税口径为「应发−个人社保公积金−专项附加」，**未**按税法做：

- 累计减除费用（5000 × 任职受雇月数）
- 累计收入 / 累计专项 / 累计专项附加
- 减本年已预扣预缴税额

产品文档已将该项列为已知缺口（`docs/product/09-payroll.md`）。本期按 SMB 最小纠偏落地，不做申报系统。

## 目标

1. 普通/实习/返聘员工：按综合所得工资薪金**累计预扣**计算本期应扣个税。
2. 兼职劳务个税逻辑保持不变。
3. 不引入新业务表；优先纯函数 + 汇总本账套本年已确认明细。
4. 单元测试覆盖关键边界；更新产品说明。

## 非目标

- 入职前其他单位累计收入/已扣税导入
- 免税收入、其他扣除等申报级分项
- 自然人电子税务局申报表
- 改历史月后自动级联重算后续月（约定：改历史需人工重算后续月份）
- 工资条 / 员工自助

## 方案选择

采用 **方案 A**：`CumulativePitRules` 纯函数即时汇总。

| 方案 | 说明 | 结论 |
|------|------|------|
| A | 算薪时汇总本年确认明细 + 当月 | **采用** |
| B | 每行落累计字段并级联回写 | 过重 |
| C | 独立累计台账表 | 过重 |

## 适用范围

| 员工类型 | 个税路径 |
|----------|----------|
| `NORMAL` / `INTERN` / `RETIREMENT` | 累计预扣（本期） |
| `PARTTIME` | 原劳务逻辑（`calculatePersonalTax(..., 1)`）不变 |

## 数据口径

### 当月（预览/重算中）

| 符号 | 来源 |
|------|------|
| 本期收入 | `payAmount`（应发） |
| 本期专项 | `totalSocialInsurance + providentFund`（个人部分） |
| 本期专项附加 | 档案 `EmployeeTaxDeduction.getTotalTaxDeduction()`（与现 `getTaxDeduction` 一致） |

### 本年历史（已确认）

取本账套 `employee_salary`：

- 同一 `employeeId`、`bookId`
- `belongDate` 年 = 所属月之年，且 `belongDate` &lt; 当月
- `deleted = n`

| 符号 | 来源 |
|------|------|
| 历史收入 | Σ `payAmount` |
| 历史专项 | Σ (`totalSocialInsurance` + `providentFund`) |
| 历史专项附加 | Σ `taxDeduction` |
| 累计已预扣 | Σ `personalTax` |

当月预览行**不**计入「累计已预扣」。

### 任职受雇月数

```
start = max(所属年-01, 入职月(entryDate))
若 entryDate 为空 → start = 所属年-01
months = 从 start 到 belongMonth（含）的月数
累计减除费用 = 5000 × months
```

入职日晚于所属月：`months = 0`，减除费用为 0（极端数据保护）。

## 计算公式

```
累计收入       = 历史收入 + 本期收入
累计专项       = 历史专项 + 本期专项
累计专项附加   = 历史专项附加 + 本期专项附加
累计减除费用   = 5000 × 任职受雇月数
累计应纳税所得额 = max(0, 累计收入 − 累计减除费用 − 累计专项 − 累计专项附加)

累计应纳税额   = 按现有 type=0 税率表：
                 累计应纳税所得额 × 税率 − 速算扣除数
                 （区间匹配逻辑与现 ConfigPersonalTax 一致；所得额≤0 则税额=0）

本期应扣个税   = max(0, 累计应纳税额 − 累计已预扣)
```

金额统一 `HALF_UP` 保留 2 位小数（与现算薪一致）。

## 字段写入约定

算薪写入 `EmployeeSalaryTemp` / 推送后的 `EmployeeSalary`：

| 字段 | 含义（本期起） |
|------|----------------|
| `personalTax` | **本期应扣个税** |
| `taxableWages` | **累计应纳税所得额**（便于对账；不再表示「当月应税工资」旧口径） |
| `taxDeduction` | 仍为**当月**专项附加合计 |

推送与凭证仍只消费 `personalTax` 等现有字段，无需改凭证模板。

## 接入点

1. 新增 `com.financial.cloud.service.hr.CumulativePitRules`（纯函数：输入累计分量 + 税率表 → 本期个税与累计应纳税所得额）。
2. `EmployeeSalaryTempService`：
   - 批量算薪 / 单行重算中，普通路径在算出当月收入与专项后，查询本年历史确认明细，调用累计规则；
   - 劳务路径不改。
3. 税率仍读 `config_personal_tax` type=0；不改配置页结构。

## UI（最小）

- 算薪预览与工资明细：保留「个税」列；可选增加只读说明或次要列：**累计应纳税所得额**（即 `taxableWages`）、**累计已扣税**（若前端易取则展示，否则后端算税即可、UI 可仅改文案提示「已按累计预扣计算」）。
- 本期最低要求：功能正确 + `docs/product/09-payroll.md` 说明；预览页一句提示即可，不强制大改表格。

## 测试

单元测试（`CumulativePitRulesTest`）至少覆盖：

1. 首月：无历史，减除 5000，低档税率。
2. 跨档：累计所得进入更高税率档。
3. 第二月：累计税额 − 首月已扣 = 本期个税。
4. 本期个税不为负（已扣偏多时为 0）。
5. 无 `entryDate`：自当年 1 月计月数。
6. 劳务/兼职不在本规则内（由服务层分支保证；规则类可不感知）。

可选：服务层测「历史从 `employee_salary` 汇总」可用 mapper mock 或窄集成，不阻塞纯函数验收。

## 风险与约定

| 风险 | 缓解 |
|------|------|
| 旧明细 `taxableWages` 语义变化 | 文档说明；历史行不回溯改写 |
| 改已确认历史月导致后续个税不准 | 文档约定需重算/重推后续月 |
| 税率表未按年累计所得区间配置 | 沿用现表；种子/配置需与国标累计税率档一致（实现时核对默认数据） |
| 入职月与无工资月份 | 任职月数按日历月计，不按「有工资月」计（与税法减除费用习惯一致） |
